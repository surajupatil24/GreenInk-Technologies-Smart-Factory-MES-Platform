## Integrity decisions

- A staging move conserves plant stock. A split appends equal negative/positive ledger rows and creates a separate labelled pallet of the same batch. The command links both movements; source and prepared labels remain queryable. Kit delivery changes location with a zero-quantity movement. Only production issue removes the prepared physical quantity.
- Reservation/consumption `RequirementQuantity` is nullable. Historical records use physical `Quantity` as their credit. Guided records retain both physical quantity and declared nominal BOM credit. Correction-factor target is calculated per batch; tolerance is applied to that target, and a valid allocation fulfills its approved nominal credit. Quantities and credits support six decimals. Credit totals cannot exceed the BOM. Reports continue to use real physical consumption; readiness uses credits. This explicit Green Ink policy needs plant UAT against intended tolerance/accounting conventions.
- Rule/factor/PPE data is snapshotted into a pick. Later manager master edits cannot rewrite active/history quantities or relax that pick's weighing limits. Stale open pick forms are rejected when displayed rule/factor versions change, so an acknowledgment cannot silently apply to newly edited safety instructions.
- Only released, unexpired raw stock with sufficient free quantity and no open issue is eligible. Source bin and label must match. An order's approval gate is checked by the API. Reservations and all foreign references are tenant/plant scoped, with composite database FKs.
- Guided reservations cannot be cancelled or moved through the quick APIs to bypass preparation; issue checks supply status/location. A plan cannot be created around outstanding quick reservations. Existing unplanned orders retain the original quick workflow.
- Serializability/xmin, command hashes, scoped unique command IDs and immutable stock movements protect concurrent picks, transfers, replenishment and count adjustments. Same command/input returns the original result; changed input is rejected. Creation and paired movements commit together.
- Replenishment cancellation is allowed only before any delivered quantity. A cancellation racing with delivery yields a single consistent result. Stock issues never silently overwrite inventory. Applying a gain/loss count requires manager review, unchanged counted system stock and preservation of reservations. Closure without adjustment is available when a fresh count is needed.
- The local buffer maximum blocks incoming staging/kit/replenishment/free/full-pallet transfers; no above-max override is offered. Verified physical counts can reveal an over-capacity condition, which the dashboard flags. No warehouse physical capacity or external accounting is inferred.
- All shown quantities preserve UOM; unrelated units are not totaled. Order/support lists are bounded200, eligible sources500 and history200; UI discloses windows. Full pagination and historical reporting remain release work.

## Validation scenarios

1. Separate full-bag pick→weigh→kit delivery→issue→complete production, with factor/tolerance snapshots and exact physical ledger reconciliation.
2. Scan wrong bin/label; missing PPE acknowledgment; missing batch factor; held/expired/insufficient stock; non-BOM material; pending engineering approval; over-credit or out-of-tolerance readings: no partial posting.
3. Concurrent picks competing for one BOM or source balance: one valid allocation, no negative/over-reserved stock. Changed input with reused command fails; unchanged retries create no duplicate stock/measurement.
4. Split corrected requirement across two batches/factors: consumed physical quantities remain distinct from summed nominal credit; production readiness reconciles.
5. Replenishment partial progress, unstarted cancellation, blocked post-start cancellation, over-delivery/capacity rejection, racing cancellation/delivery and safe retry.
6. Return unissued material, restore credit/free stock and preserve history; deny return after issue. Dedicated stock cannot bypass gates through quick transfer/cancel APIs.
7. Gain/loss report leaves balances unchanged, blocks proposed source; reviewed count posts once; stale count or count below reservations fails; actor permissions and foreign scope remain enforced.
8. Static/demand buffers use real balances and outstanding requests; no duplicate suggested quantity. Manual preparation/kit QR/CSV/mobile/dark UI are verified separately from device integration.
